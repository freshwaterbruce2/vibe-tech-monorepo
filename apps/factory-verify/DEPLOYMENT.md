# FactoryVerify Deployment

This app was generated by `@vibetech/factory:saas`.

## Local ship preflight

Run this before attempting a live deploy:

```powershell
pnpm nx run factory-verify:ship:check
```

What it proves locally:

- shared packages build cleanly
- frontend and API compile cleanly
- the compiled API passes health/auth/pro-route, email, AI-metering, and Stripe smoke checks
- missing Stripe or deploy credentials are reported explicitly

## Deployment shape

- Frontend: Vercel static Vite deployment
- Backend: Railway Fastify deployment
- Billing: Stripe Checkout in test mode first
- Monetization: shared `@vibetech/monetization`, `@vibetech/billing`, `@vibetech/payments`, `@vibetech/email`, and `@vibetech/ai` packages

## Railway backend steps

1. Deploy from the monorepo root.
2. Use [railway.json](./railway.json).
3. Set the backend environment variables above.
4. Confirm `GET /api/health` returns `{"ok":true,"app":"factory-verify"}`.
5. Confirm `GET /api/billing/demo-checkout` returns a Stripe Checkout URL once `STRIPE_SECRET_KEY` is set.
6. Configure Stripe to send Checkout and subscription events to `/api/webhooks/stripe`.

## Stripe Webhook Bus

Generated SaaS apps include `/api/webhooks/stripe`, powered by the shared `@vibetech/billing` Stripe Webhook Bus. Configure `STRIPE_WEBHOOK_SECRET` in production so Stripe signatures are verified from the raw request body. The generated starter logs Checkout and `customer.subscription.*` events; replace the in-memory processed-event set with your app database when adding persistent entitlements.

## Vercel frontend steps

1. Import the repo in Vercel.
2. Set the project root to `apps/factory-verify`.
3. Enable source files outside the root directory so pnpm workspace packages are available.
4. Install command: `cd ../.. && pnpm install --frozen-lockfile --filter ./apps/factory-verify...`
5. Build command: `pnpm run build:shared:api && pnpm run build`
6. Output directory: `dist`
7. Set the frontend environment variables above.
8. Use [vercel.json](./vercel.json) so `/terms` and `/privacy` resolve to the SPA entry.
