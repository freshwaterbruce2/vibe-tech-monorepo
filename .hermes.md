# VibeTech Monorepo Coding Conventions

These rules apply to any agents working in the VibeTech monorepo.

## Package Manager & Tooling
- **Package Manager**: Strictly use `pnpm` (v10.28.2+). Do not use `npm` or `yarn`.
- **Chaining Commands**: Always chain commands with semicolons (`;`) in PowerShell 7+ — never use `&&`.
- **Nx Targets**: Use Nx tasks for building, testing, and linting. Prefer Nx commands from the workspace root (e.g. `pnpm nx build <project>`).

## Storage & Paths Policy (Critical)
- **Code Path**: All source code and build settings live at `C:\dev\`.
- **Data/Logs/Cache**: All databases, temporary directories, cache files, and logs MUST reside on the `D:\` drive (e.g., `D:\databases\`, `D:\logs\`, `D:\learning-system\`).
- **No C: Pollution**: Never write database files, SQLite databases, runtime logs, or telemetry outputs to `C:\dev\`.

## Code Quality Standards
- **File Length soft limit**: Keep components and files under 500 lines. Targets for components are 200–300 lines. Split logic early.
- **Type Safety**: Enforce TypeScript strict mode. Avoid using the `any` type without justification.

## Build Requirements
- **Vite Production Builds**: Enforce `cross-env NODE_ENV=production` for all production builds to prevent compiler emission of `jsxDEV` calls, which crash on startup when React resolves to its production bundle.
