## Findings

### F-001 [vibe-shop] Fragile auto-generated WebMCP tools (CRITICAL tech debt)
Status: [ ] OPEN
File: apps/vibe-shop/src/lib/webmcp.tools.ts (1380 lines, auto-generated by @keak/webmcp-core)
Problems:
1. 51 tools registered, ~40 of which are single-purpose "navigate to one hardcoded
   product UUID" tools — burns agent context windows and breaks whenever the catalog changes.
2. Every URL hardcodes http://localhost:3010 — broken in production outright.
3. search_products monkey-patches window.fetch and only restores it on success;
   on timeout the patched fetch leaks permanently. Also depends on a brittle
   positional CSS selector (html > body > main > header > div > div > form).
4. Navigation uses window.location.href + setTimeout(2000) — full page reloads,
   races, no SPA routing.
5. Tools never unregister (no AbortSignal), violating cleanup contract.
6. Discovery: @keak/webmcp-core is a Playwright CLI GENERATOR, not a React hooks
   library — it has no hooks to convert to. The in-house equivalent is
   packages/shared-utils/src/webmcp (WebMCPManager: native/polyfill detection,
   AbortSignal unregistration, declarative forms). Per no-duplicates rule, that
   is the correct foundation.
Planned fix:
- New apps/vibe-shop/src/lib/webmcp.hooks.tsx: useStorefrontTools() React hook
  registering 4 parameterized tools (search_products, browse_category,
  view_product, open_page) through WebMCPManager, using next/navigation router
  (SPA, relative paths, no localhost), AbortController cleanup on unmount.
- WebMCPProvider.tsx switches to the hook.
- Delete generated webmcp.tools.ts (generator raw output stays in /webmcp-output/,
  which is already gitignored).
- Add @vibetech/shared-utils workspace dep to vibe-shop.
- Category tool takes a slug string (catalog is DB-backed via Prisma; seed slugs:
  electronics, home-garden, fashion, health-beauty, toys-hobbies, sports).
- All descriptions < 500 chars, param descriptions < 150 chars.

### F-006 [packages/games] Chess AI minimax runs on the main thread
Status: [x] RESOLVED
packages/games/src/chess/lib/chessAi.ts + components/PlayMode.tsx:40-50.
chooseAiMove (depth 2, branching 20, and mobilityScore constructs a new Chess
per evaluation) executes inside window.setTimeout — deferred but still blocking
